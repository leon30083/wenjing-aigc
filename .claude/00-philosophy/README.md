## 核心理念总结

### 三大哲学

| 哲学 | 核心思想 | 实践方法 |
|------|---------|---------|
| **胶水编程** | AI 连接代码，人审连接 | 只连接成熟模块，不生成新代码 |
| **强约束** | 约束不是限制，而是保护 | 35条约束规则，防止已知错误 |
| **血的教训** | 10分开发，7分找资料 | 调研优先，避免重复犯错 |

### 开发公式

```
胶水代码 = 接口适配 + 数据转换 + 流程编排

时间分配 = 70% 调研 + 20% 编码 + 10% 测试

错误预防 = 阅读文档 + 查看错误模式 + 遵循约束
```

## 常见问题

### Q1: 为什么要先阅读哲学层文档？

**A**: 哲学层文档是整个开发规范的基础：
- **胶水编程**告诉你"怎么做"（开发范式）
- **强约束**告诉你"不能做什么"（开发红线）
- **血的教训**告诉你"为什么要这样做"（经验总结）

理解这些哲学理念后，其他层的技术文档会更容易理解。

---

### Q2: 胶水编程和传统编程有什么区别？

**A**:

| 维度 | 传统编程 | 胶水编程 |
|------|---------|---------|
| 代码来源 | 人写代码 | AI 连接代码 |
| 开发重点 | 实现功能 | 连接模块 |
| 调试重点 | 逻辑错误 | 集成错误 |
| 维护成本 | 高 | 低 |

---

### Q3: 35条约束如何记忆？

**A**: 不需要全部记忆，只需：
1. 理解核心原则（胶水编程、双平台差异、角色引用）
2. 使用自动化工具（ESLint、Pre-commit Hook）
3. Code Review 时检查约束合规性
4. 遇到错误时查阅约束映射表

高频约束（Top 5）必须记住：
- #29: 禁止硬编码 API 端点
- #30: 必须处理双平台差异
- #31: 禁止假设任务ID字段名
- #32: 禁止使用过短的轮询间隔
- #33: 角色引用必须保留

---

### Q4: 调研需要多长时间？

**A**: 根据任务复杂度：
- **简单任务**（如添加新节点）：15-30 分钟调研
- **中等任务**（如集成新 API）：30-60 分钟调研
- **复杂任务**（如重构架构）：1-2 小时调研

**调研回报**: 调研 1 小时 = 节省 3 小时调试

---

### Q5: 如何应用这些哲学？

**A**: 实践步骤：
1. **开发前**: 阅读 [血的教训]，制定调研计划
2. **开发中**: 遵循 [28条强约束]，使用代码模板
3. **开发后**: 更新错误模式库，记录新的教训
4. **Code Review**: 检查约束合规性，分享经验

## 实践建议

### 日常开发

1. **开始新任务前**
   - 快速浏览错误模式库
   - 确认相关约束规则
   - 制定调研计划

2. **编码过程中**
   - 使用代码模板
   - 遵循约束规则
   - 添加错误处理

3. **提交代码前**
   - 运行预提交检查清单
   - 确认约束合规性
   - 更新相关文档

### Code Review

1. **检查清单**
   - 是否违反强约束？
   - 是否使用了成熟模块？
   - 是否处理了双平台差异？
   - 是否保留了角色引用？

2. **反馈重点**
   - 指出违反的约束编号
   - 提供正确的代码示例
   - 解释背后的哲学原理
