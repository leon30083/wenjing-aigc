## 1. 测试工作流文件规范

### 1.1 命名规范

```
{功能}-{场景}-{版本}.json

示例:
- single-video-v1.json          # 单个视频生成 v1
- batch-video-v1.json           # 批量视频生成 v1
- character-creation-v1.json     # 角色创建 v1
```

### 1.2 元数据格式

每个测试工作流必须包含完整的元数据：

```json
{
  "name": "测试工作流名称",
  "description": "详细描述测试场景",
  "category": "character-video | storyboard | basic",
  "version": "1.0.0",
  "author": "AI | Human",
  "tags": ["标签1", "标签2", "E2E"],
  "testPlan": [
    "步骤1: 描述",
    "步骤2: 描述",
    "步骤3: 描述"
  ],
  "nodes": [...],
  "edges": [...],
  "viewport": { "x": 0, "y": 0, "zoom": 1 },
  "expectedResults": {
    "category": {
      "description": "验证描述",
      "checks": [
        "检查项1",
        "检查项2"
      ]
    }
  },
  "createdAt": "2026-01-18T00:00:00.000Z",
  "updatedAt": "2026-01-18T00:00:00.000Z"
}
```

### 1.3 存放位置

```
tests/workflows/
├── README.md                          # 测试工作流说明
├── character/                         # 角色相关测试
│   ├── single-video.json              # 单角色视频 ⭐
│   └── batch-video.json               # 批量角色视频 ⭐
├── storyboard/                        # 故事板测试
│   └── basic-storyboard.json
└── basic/                             # 基础功能测试
    ├── simple-connection.json
    └── complete-nodes.json
```

## 2. AI + 用户协作测试流程

### 2.1 测试流程图

```
AI 编写测试工作流
    ↓
用户手动导入前端
    ↓
用户手动验证功能
    ↓
记录问题和改进
    ↓
更新测试工作流
```

### 2.2 AI 职责

**创建测试工作流**:
- ✅ 根据需求创建完整的测试工作流 JSON
- ✅ 包含详细的 testPlan（测试步骤）
- ✅ 包含 expectedResults（预期结果）
- ✅ 验证 JSON 格式正确

**验证工作流正确性**:
- ✅ 检查节点 ID 唯一性
- ✅ 检查 Handle 连接正确性
- ✅ 检查数据传递格式正确性

### 2.3 用户职责

**导入测试工作流**:
- ✅ 启动前后端服务器
- ✅ 打开浏览器 (http://localhost:5173/)
- ✅ 通过控制台导入工作流

**手动验证**:
- ✅ 按照 testPlan 执行测试步骤
- ✅ 验证 expectedResults 中的检查项
- ✅ 记录发现的问题

**反馈问题**:
- ✅ 描述问题现象
- ✅ 提供复现步骤
- ✅ 附上截图或日志

## 3. 测试验证清单

### 3.1 视觉验证

- [ ] **节点位置**: 所有节点显示在正确的位置
- [ ] **节点样式**: 每个节点类型有正确的颜色和样式
  - 输入节点：蓝色 (#3b82f6)
  - 处理节点：绿色 (#10b981)
  - 输出节点：浅蓝 (#0ea5e9)
- [ ] **连接线**: 所有边显示为可点击的SVG线（或通过状态验证）
- [ ] **Handle显示**: 节点的输入/输出Handle可见

### 3.2 交互验证

- [ ] **拖拽节点**: 可以自由移动节点
- [ ] **选择节点**: 点击节点可以选中
- [ ] **删除节点**: 选中后按Delete可以删除
- [ ] **删除连接**: 点击连接线后可以删除

### 3.3 数据流验证

#### 3.3.1 角色数据传递 ⭐ Error 55

- [ ] 选择角色后，VideoGenerateNode 的 `connectedCharacters` 不为空
- [ ] `connectedCharacters` 包含完整对象（不是仅ID）
- [ ] 格式正确：`[{id, username, alias, profilePictureUrl, permalink}, ...]`

#### 3.3.2 角色引用双显示

- [ ] 输入框显示别名（`@测试小猫`）
- [ ] API 使用真实ID（`@6f2dbf2b3.zenwhisper`）
- [ ] 角色引用格式正确（不带花括号）

#### 3.3.3 任务结果显示

- [ ] 执行视频生成后，TaskResultNode 显示任务ID
- [ ] 轮询状态正确更新（IN_PROGRESS → SUCCESS）
- [ ] 进度百分比正确更新（0% → 100%）
- [ ] 视频URL正确显示
- [ ] 支持下载视频

## 4. 自动化测试 vs 手动测试

### 4.1 Playwright 自动化测试

**优点**:
- ✅ 快速、可重复
- ✅ 状态正确性验证
- ✅ 可集成到 CI/CD

**缺点**:
- ❌ 看不到可视化效果
- ❌ 不能完全模拟用户操作

**适用场景**:
- 状态管理验证
- 连接正确性验证
- 回归测试

### 4.2 手动测试

**优点**:
- ✅ 真实用户场景
- ✅ 可视化效果验证
- ✅ 发现 UI/UX 问题

**缺点**:
- ❌ 耗时、不可重复
- ❌ 依赖人工操作

**适用场景**:
- 用户体验验证
- UI 效果验证
- 新功能探索

### 4.3 测试策略

**建议**: 两者结合使用
- 开发阶段：使用自动化测试快速验证
- 发布前：使用手动测试确认用户体验
