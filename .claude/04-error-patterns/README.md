## 错误预防

### 三层防护

```
┌─────────────────────────────────────────────────────────┐
│  第一层：约束规则                                         │
│     35 条约束规则，防止已知错误                            │
│     → 遵循约束，避免 80% 的错误                           │
├─────────────────────────────────────────────────────────┤
│  第二层：Pre-commit Hook                                 │
│     自动化检查，捕获违规代码                              │
│     → 提交前拦截，避免引入错误                            │
├─────────────────────────────────────────────────────────┤
│  第三层：Code Review                                     │
│     人工审查，发现复杂问题                                │
│     → 最终防线，确保代码质量                              │
└─────────────────────────────────────────────────────────┘
```

### 预防检查清单

**提交前检查**:
- [ ] 运行 `npm run validate:all`
- [ ] 运行 `npm run test:all`
- [ ] 检查是否违反约束规则
- [ ] 更新相关文档

**代码审查检查**:
- [ ] API 路径是否包含 `/api/` 前缀？
- [ ] 是否处理了双平台差异？
- [ ] 是否兼容 `id` 和 `task_id`？
- [ ] 轮询间隔是否 ≥ 30 秒？
- [ ] 角色引用是否保留？
- [ ] 是否使用了 `useNodeId()`？
- [ ] useEffect 依赖是否正确？

## 核心约束

### 高频约束（Top 5）

| 约束 | 描述 | 违规后果 |
|------|------|----------|
| **#29** | 禁止硬编码 API 端点 | 404 错误 |
| **#30** | 必须处理双平台差异 | 兼容性问题 |
| **#31** | 禁止假设任务ID字段名 | undefined 错误 |
| **#32** | 禁止使用过短的轮询间隔（≥30秒） | 429 错误 |
| **#33** | 角色引用必须保留 | 角色丢失 |

## 错误处理流程

### 发现错误时

```
1. 识别错误
   ↓
2. 搜索错误模式库
   ↓
3. 应用解决方案
   ↓
4. 验证修复
   ↓
5. 更新文档（如有新模式）
```

### 记录新模式

当发现新的错误模式时：

1. **添加到错误库**
   ```markdown
   ### 错误56: [新错误标题]
   **严重程度**: ⭐⭐
   **描述**: [错误描述]
   **根本原因**: [原因分析]
   **解决方案**: [修复方案]
   ```

2. **映射到约束**
   ```javascript
   // 如果违反了现有约束
   错误56 → 约束#XX

   // 如果需要新约束
   创建约束#36
   ```

3. **添加预防措施**
   ```markdown
   - [ ] ESLint 规则
   - [ ] Pre-commit Hook
   - [ ] 单元测试
   ```

## 快速参考

### API 相关错误

| 错误 | 问题 | 解决方案 |
|------|------|----------|
| 错误17 | API 端点缺少前缀 | 使用完整路径 `/api/video/create` |
| 错误3 | 缺少 `/api/` 前缀 | 添加前缀到所有 API 调用 |
| 错误38 | 查询端点格式错误 | 根据平台使用不同端点 |
| 错误39 | 任务ID字段不兼容 | 使用 `result.data.id \|\| result.data.task_id` |

### React Flow 相关错误

| 错误 | 问题 | 解决方案 |
|------|------|----------|
| 错误4 | data.id 是 undefined | 使用 `useNodeId()` Hook |
| 错误16 | 节点间数据传递错误 | 源节点直接更新目标节点 |
| 错误29 | useEffect 无限循环 | 避免依赖 `data` 对象 |
| 错误37 | data.id 再次 undefined | 使用 `useNodeId()` Hook |
| 错误52 | 节点数据未同步 | 一次 `setNodes()` 更新多个节点 |

### 角色系统相关错误

| 错误 | 问题 | 解决方案 |
|------|------|----------|
| 错误48 | 优化节点错误使用双显示 | 只使用真实 ID |
| 错误55 | 角色引用格式错误 | 使用 `@username` 格式（不带花括号） |

## 常见问题

### Q1: 如何查找相关错误？

**A**: 使用以下方法：
1. 按类型浏览（API、React Flow、角色系统等）
2. 搜索关键词（如 "任务ID"、"轮询"）
3. 查看高频错误（Top 5）
4. 使用约束映射表

### Q2: 如何避免已知错误？

**A**: 遵循三层防护：
1. **约束规则** - 了解 35 条约束
2. **Pre-commit Hook** - 自动化检查
3. **Code Review** - 人工审查

### Q3: 发现新错误怎么办？

**A**:
1. 记录错误信息（现象、复现步骤）
2. 分析根本原因
3. 添加到错误模式库
4. 映射到相关约束
5. 更新预防措施

### Q4: 如何使用约束映射表？

**A**:
1. 查看约束编号
2. 找到相关错误
3. 了解预防措施
4. 应用到代码审查
