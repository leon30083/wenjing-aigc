## 📋 当前问题分析

### 问题 1: 规则文件分散，AI 加载效率低

**现状**:
```

├── quick-reference.md    (479 行) - 开发流程
├── base.md              (1,193 行) - 技术栈
├── code.md              (544 行) - 代码规范

├── docs.md              (451 行) - 文档规范
└── ...
```

**问题**:
- 规则文件数量多，AI 不确定加载哪个
- 缺少明确的"任务 → Skill"映射
- 自动化编程规则未与 Skill 系统集成

---

### 问题 2: Skill 与规则文件未打通

**现状**:
```
.claude/skills/winjin-dev/
```

**问题**:

**现状**:


### 方案 2: 在自动化编程规则中加入强制指令

```markdown
## 8. 强制使用 Skill 规则 ⭐ 新增

### 8.1 任务类型 → Skill 映射

| 任务类型 | 必须使用的 Skill | 规则文件 |
|---------|----------------|---------|
| React Flow 节点开发 | `/skills node-dev` | quick-reference.md, base.md (React Flow) |

**开发前**:
```
1. AI 识别任务类型
2. 自动调用对应的 Skill
3. Skill 返回"允许开发的规则和约束"
4. AI 按照约束进行开发

```
**示例对话**:
```
User: 创建一个新的视频生成节点

      - 必须使用节点模板 (03-node-development/node-templates.md)
      - 必须验证 Handle 连接 (handle-connections.md)
      - 必须运行 MCP 测试 (automation-rules.md 第 2 节)

    开始开发...
```

### 8.3 违规检测机制

**如果 AI 未使用对应 Skill**:
```

- 实际: 未使用 Skill

```

**实现方式**:
- 在 automation-rules.md 开头添加"强制规则"
- AI 在开始开发前检查是否已加载对应 Skill
- 使用 regex 检测对话历史中的 Skill 调用
```

### 方案 3: 规则文件模块化重构

#### 3.1 当前结构问题

```
.claude/rules/
├── base.md              (1,193 行) - 包含所有技术栈
├── code.md              (544 行) - 包含所有代码规范
└── ...
```

**问题**: 文件太大，AI 不确定读取哪个章节。

#### 3.2 模块化结构

```
.claude/rules/
├── index.md             # 规则入口（类似 skill package.json）
├── modules/
│   ├── node-development/
│   │   ├── index.md     # 节点开发规则入口
│   │   ├── basics.md    # 基础概念
│   │   ├── handles.md   # Handle 连接规范
│   │   ├── templates.md # 节点模板
│   │   └── testing.md  # 测试规范
│   ├── api-integration/
│   │   ├── index.md
│   │   ├── endpoints.md
│   │   ├── platforms.md # 双平台差异
│   │   └── errors.md    # API 错误模式
│   └── automation/
│       ├── index.md
│       ├── triggers.md  # 触发规则
│       ├── testing.md   # 测试规则
│       └── collaboration.md # 协作规则
└── error-patterns/
    ├── index.md
    ├── api.md
    ├── react-flow.md
    └── ...
```

**优势**:
- 按任务类型组织规则
- AI 只需加载 `modules/xxx/index.md`
- index.md 自动引用相关子模块

## 📝 关键问题需要思考

### 问题 1: 如何检测 AI 是否使用了正确的 Skill？

**方案 A**: 检测对话历史
```
检测对话中是否包含: "/skills node-dev"
如果不包含 → 提示违规
```

**方案 B**: 在 Skill 开发阶段添加"前置检查"
```
Skill 开发模式:
1. AI 识别任务类型
2. 自动生成: "建议使用 /skills xxx"
3. 等待用户确认
4. 加载 Skill 后才开始开发
```

**方案 C**: 使用 settings.json 强制配置
```json
{
  "requiredSkill": "node-dev",
  "taskType": "node-development"
}
```

**推荐**: 方案 B + 方案 C 组合

---

### 问题 2: 规则文件如何"构建"成 Skill？

**方案 A**: 静态构建（脚本）
```bash
build-skill.sh --type node-development
# 从 rules/modules/node-development/*.md
# 生成 skills/node-dev/SKILL.md
```

**方案 B**: 动态加载（AI 自动）
```
AI 执行:
1. 读取 rules/modules/node-development/index.md
2. index.md 包含引用: #include: basics.md
3. AI 自动加载被引用的文件
```

**方案 C**: Skill 预处理（构建时）
```
Skill 文件本身包含"前置要求":
---
requires:
  - rules/modules/node-development/basics.md
  - rules/modules/node-development/handles.md
---

AI 加载 Skill 时自动加载 requires 中的文件
```

**推荐**: 方案 C（最简单，兼容性好）

---

### 问题 3: 如何避免规则文件重复？

**当前问题**:
- `SKILL.md` 包含部分规则内容
- `base.md` 也包含相同内容
- 导致更新困难

**解决方案**:
1. **规则文件作为唯一数据源**
   - `SKILL.md` 只包含引用链接
   - 不重复规则内容

2. **使用 `#include` 语法**
   ```markdown
   ## API 规范

   #include: ../rules/modules/api-integration/endpoints.md
   #include: ../rules/modules/api-integration/platforms.md
   ```

3. **AI 自动解析 include**
   - AI 加载 SKILL.md 时
   - 遇到 `#include` 时自动加载引用文件
   - 合并内容后呈现
